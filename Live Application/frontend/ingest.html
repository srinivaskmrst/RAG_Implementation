Bank documents Guardrails

Folder Bank_Documents → Pinecone namespace bank-docs · –

  1. PII masking – PAN XXXXX1234X, Aadhaar XXXX XXXX 1234, account numbers (last 4 digits), card numbers (first 6 + last 4), mobile, e-mail and date of birth are masked before chunking and embedding – raw personal data never reaches Pinecone or the LLM.
  2. Prompt-injection scan – chunks that contain instructions aimed at the AI are quarantined (not stored).
  3. Classification & access metadata – every vector keeps its classification (INTERNAL … HIGHLY_CONFIDENTIAL; missing → CONFIDENTIAL), customer and document category for the role-based access filter at retrieval time. Files over 20 MB are rejected.

How ingestion works (both datasets)

  1. Document hash check – SHA-256 of the file. If this hash is already in the vector database, the document is unchanged and skipped.
  2. Chunk hash check – for a new or changed document, every chunk's SHA-256 is its vector id: chunks already in the database are skipped, only new chunks are embedded and inserted, outdated chunks are removed.
  3. Delete removes every vector of that dataset only (its whole Pinecone namespace) – the other dataset is not touched. Click Ingest again to rebuild it.
